So let's say this right up front. There is no way on this planet that a changelog can cover everything in this release. The Feature Highlights from the past six weeks cover the big features. These notes cover the rest, grouped by theme. The full changelog at the bottom lists every pull request, and we're doing a better job of labelling each one, so you can tell whether it adds something new, fixes something, or does something else.

**How we got here**

We could build a release this size because, for a good chunk of this summer, we had more developers working on the projects than ever before. Things have slowed down since.

You've heard us talk about tech debt. If you haven't, here's what it means. Tech debt is the cost of old shortcuts. Code that was written in a hurry to get a feature out, or written years ago for a much smaller program, has to be worked around every time we change something near it. Think of a house where the wiring was added one room at a time. Every new light switch takes longer to put in, and it's more likely to blow a fuse somewhere else. Paying down tech debt is the rewiring. You don't see it, but everything after it gets faster and safer to build.

With all the code we've added, changed or touched in the last six months, we've made sizable dents in that debt, and it's finally going to start paying dividends. New features will get easier to build, and we can catch up on things we haven't been able to implement. We're also looking at improvements to the MegaMek interface that line up with the interface changes already made in MekHQ. MegaMekLab will follow, but for the next few cycles the focus stays on MegaMek and MekHQ.

So long-time players will open this release and, in some ways, think nothing has changed. In other ways, everything will feel different.

<div class="corerules-callout" markdown="1">
<p class="corerules-callout-title">A word from the team</p>

That leads into something important, and we want to take a moment for it.

We are a volunteer team. Looking at what the programs already do, and what rules still need to be implemented, we've realized we need a slightly different approach from this release on. We've always tried to fit everyone's needs within what the programs can do. We're not going to stop taking requests, but we are going to be more selective about which ones we build. We can't implement something just because one player asks for it on the tracker or on Discord. It needs to be a need shared by a larger group of players, and the developers need to see its importance too. That doesn't mean it will never happen. It means being honest about expectations. We are the guardians of these projects, and we have to move them forward in the way we think is right.

There's one more thing we need to call out, because it's a pattern we've seen more of this year. People are forgetting that most of our developers work full-time jobs. They do this for fun, as a hobby, and for the love of the community. Some of the comments and reactions aimed at MegaMek and the other projects have been very disheartening. Please remember that we're more than the handles you see on the screen. We're people too. We have lost developers in the past because of how the community reacted to decisions we made, and that has been true for as long as the projects have existed.

So we ask for a little understanding, a little kindness, and a little trust. We love this game and this universe every bit as much as you do. But in the end, we have to make decisions based on what's right for the programs' long-term success, and for the people who volunteer to code them.

Probably the biggest change landing with this release, and one that will be critical going forward, is the new **MegaMek Launcher**. This is now the way you get the programs.

Why a launcher? Over the years we've realized that we created an experience that isn't ideal for players, in two big ways.

The first is what happens after a release. We ship a new version, and a week or so later we find a crippling bug. Then we either have to rush out an emergency release, or tell everyone to wait for the next release cycle. Neither is good. And when we start a release cycle knowing there's a critical bug out there, it changes how we run that cycle. Instead of giving it the three months it really should have, we race through it to get something out in two months just to fix that bug.

The second is the barrier to entry, which has always caused a lot of problems. You need to install Java, and then the questions start:

<div class="corerules-callout release-questions" markdown="1">
Do I have the right version of Java? Is my Java up to date?

Now I need to update my Java. Now I need to uninstall my Java, but it didn't install right, so now my Java is broken.

How do I fix my broken Java? How do I unzip the program?

What do you mean the Windows unzipper isn't good enough and I need to use 7-Zip?
</div>

We get these questions every single release. Illiani called it *The Wall* in the Launcher post, and we know a lot of new players bounce right off it.

We live in a world where players click a button on Steam, or any of the other launchers out there, and the game just works. We wanted that for MegaMek too. Alitar, our user interface lead, spent this cycle building it.

The Launcher post covers what it does: Java handled for you, several versions side by side, and one-button upgrades. A few things it didn't mention. It can bring in the copies you already have. There's a View Logs button for when you need to send us a bug report, and the latest news shows up right in the window. And you choose when to upgrade, so nothing changes in the middle of your campaign.

## A New Release Rhythm: Core Releases and Experimental Releases

Over MegaMek's lifetime, our approach to releases has changed again and again.

Way back, we had a **stable** release and a **development** release. It wasn't uncommon to sit on a stable release for a couple of years while the development releases moved on. Those ranged from really good releases that honestly should have been called stable, to really unstable ones that should never have been released at all.

We then moved to **milestones**. A milestone was simply a release we marked after the fact. If we felt a development release was a good one, we declared it a milestone, and development releases kept moving forward the same way as before.

The Launcher changes things for us, and that's why we're now adopting two streams: **Core releases** and **Experimental releases**. The Launcher post's [A New Model of Releases](https://megamek.org/2026/11/02/Feature-Highlight-The-MegaMek-Launcher.html#a-new-model-of-releases) section covers how often each one ships. Here's what they mean for you.

**Core releases are releases we feel we can stand on.** 0.51.01 is our first one, and it's where almost everyone should be.

**Experimental releases are something you opt into,** and we need to say this in very clear language. ### Core Rules and Walk-on Deployment

Back in August we did something we'd never done before: a MegaMek-only release. [0.51.00.1, the Core Rules Release](https://megamek.org/2026/08/14/MegaMek-Core-Rules-Release-0.51.00.1.html) brought MegaMek in line with Catalyst's *BattleTech Core Rulebook*, and [Core Rules Phase One](https://megamek.org/announcements/development/2026/08/11/Core-Rules-Phase-One-and-a-MegaMek-Only-Release.html) explains why we did it that way. If you play MegaMekLab or MekHQ, this is the first time all of that work reaches you.

Since we launched the Core Rules, we've had a lot of very positive feedback on how they play. It also helped that we'd already run the playtests in MegaMek. We've kept implementing, refining and fixing the Core Rules since then, and we're happy to announce that we've brought in one of the most wanted features in MegaMek: **walk-on deployment**.

It's always on when you play under the Core Rules, and MegaMek now defaults to the Core Rules. Playing Total Warfare? Turn on the **Walk-on Deployment** game option and you can use it there too.

Here's what changes. Your units don't appear on the map in a separate Deployment phase any more. They march on from your map edge during the Movement phase, and deploying is part of their move.

- **How it works.** In the Movement phase, your first click picks the edge hex the unit enters on. Your second click plots its move from there. Press **Escape** to clear both and pick a different hex. Press **Move**, and the unit enters and moves in one go. For example, your Marauder MAD-3R enters on the north edge, pays for the terrain it steps onto, and spends the rest of its MP walking into the woods.
- **The edge is the edge.** Deployment zones are one hex deep: the map edge itself. The lobby's player settings tell you so.
- **Not every unit walks on.** Units set to deploy **Any** or **Center**, and units with their deployment round set to **Pre-game**, are placed the old way before the game starts. Immobile units skip movement and initiative entirely.
- **It works with the rest of the game.** Units carrying troops, vehicles pulling trailers (the train turns to fit if it has to), individual initiative, jumping, aerospace on space maps, and fighters coming back after flying off all walk on properly. The movement envelope shows the right reach for a unit that hasn't entered yet.
- **The bots walk on too.** We've trained both Princess and CASPAR to use it ([Princess and CASPAR, Round Two](https://megamek.org/2026/11/15/Feature-Highlight-Princess-and-CASPAR-Round-Two.html), "Smarter Decisions").

<div class="corerules-callout release-warning" markdown="1">
<p class="corerules-callout-title">Please report anything odd</p>

Walk-on deployment has had extensive testing, but it's also been one of the most complex and challenging things we've ever had to implement. Roundtop has done a spectacular job with it. If you're playing with walk-on deployment, and under the Core Rules you are, please report any oddities or unusual behaviour with Report a Bug.
</div>

When we introduced the Core Rules, we asked for extra eyes on a few things that sit in very old code ([Where We'd Like Eyes](https://megamek.org/2026/08/14/MegaMek-Core-Rules-Release-0.51.00.1.html#where-wed-like-eyes)): superheavy Mek ammo and explosive weapon crits, underwater energy weapons, line of sight to submerged Meks, and seatbelt Piloting Skill Rolls. #### Game Master Tools (beta)
In 0.51.00.1 we rebuilt Game Master mode around the Edit Damage console ([Core Rules Phase One](https://megamek.org/announcements/development/2026/08/11/Core-Rules-Phase-One-and-a-MegaMek-Only-Release.html), "Game Master mode, rebuilt"). This release goes further: the Game Master now controls the battlefield itself, not just the units on it. [What's Coming](https://megamek.org/2026/10/16/0.51.01-what's-coming.html) has videos of it in action. To become the Game Master, request the role from the **Commands** menu, and the other players vote on it.
- **Reshape the battlefield mid-game.** Right-click a hex for **Change Terrain** or **Modify Building** (both still marked **alpha** in the menus). They work like a paint brush: set what you want, then paint one hex or seven at a time. Flood a valley, burn the woods down to light, raise a hill, put up a warehouse, or knock one flat. MegaMek refuses anything illegal and tells you why, and **Undo** takes back the last change.
- **Bring a player into a game in progress.** **Commands → Set Up Player** does it in one dialog: pick a team, choose the edge they come in from, then **Apply and Reinforce** from a MUL file or the unit generator. Mid-game reinforcements now live under the Game Master menu, so players can't hand themselves a fresh lance any more.
- **Hand out forces from the lobby.** Add Unit, Create Random Army, the Force Generator and Load MUL can all put units on *any* player's force. Before, they quietly landed on yours.
- **A deeper Edit Damage console.** Flip any unit's equipment on or off, or change its mode, from ECM and C3 to MASC and AMS. Charge Bombast Lasers and PPC Capacitors. Mark weapons Jammed or Fired, mark Mek locations Breached or Blown Off, and **Explode** explosive equipment. Set per-unit ejection, add a this-round **Target Modifier**, and **Restore Unit** now brings back blown-off limbs.
- **Give orders to bot units.** Tell a bot unit to withdraw now, fight to the death, or follow its bot's usual rules. With CASPAR, you can also give enemy lances routes and roles.
- **Run the objectives.** Place, edit and remove victory points mid-game, and write what a scan reveals.
- **Fixed along the way.**
  - **Skip Current Turn** skips any turn. It used to work only on a disconnected player's turn, so nine times out of ten it just said "skip failed". Other players can still only skip a stuck turn.
  - **Start a Fire** and **Start a Firestorm** work without the TacOps Start Fires option, which is really about attacks setting things alight.
  - **The minimap shows the right colours.** A Game Master with no units, or an observer watching the bots fight, sees each side in its lobby colour instead of everything in enemy red.

#### Rules
- **Recon Cameras are in** (TO:AUE p.150), on the ground, in the air and as a bomb pod. And yes, the bots know how to use them.
- **Oblique Artilleryman finally reaches further.** The pilot ability (CamOps p.78) was supposed to extend artillery range, and now it does.
- **Artemis and Apollo have an off switch.** Artemis IV, Artemis V, Proto Artemis and Apollo now have On and Off modes, just like ECM.

### Bug Fixes

Here are the fixes you're most likely to have run into, grouped by what you'd be doing at the time. For everything else, see **Help > Release Notes** in MegaMek, or the full changelog at the bottom of this post. The bot fixes, about 30 of them including the bots' artillery, are in the [Princess and CASPAR highlight](https://megamek.org/2026/11/15/Feature-Highlight-Princess-and-CASPAR-Round-Two.html).

#### Infantry
We fixed a lot of infantry bugs this cycle, and [Boots on the Ground](https://megamek.org/2026/10/30/Feature-Highlight-Boots-on-the-Ground.html) covers most of them. Here's what it didn't mention:
- **Missiles hit the way they should.**
  - Fighter missiles against infantry do the right damage.
  - iATM IMP missiles fired at an airborne fighter actually do something now: damage, plus their IMP effects.
- **Battle armor.**
  - Autoconfig and Randomize only load rounds battle armor can use (no more BattleMek rounds like Acid or Tandem-Charge), and the bins keep their shot count. Clan SRM, LRM and ATM bins now actually change when you autoconfig.
  - Some suits with turrets wouldn't load at all. Now they do.
  - The Myomer Booster has the right weight and cost, and AP, modular and turret weapon mounts cost what they should.
- **Aimed shots don't crash the game.** Aiming at a tank or battle armor squad in partial cover used to bring the whole thing down.
- **Conventional infantry.**
  - Mechanized platoons (hover, wheeled or tracked) get their fifth squad.
  - Platoons carrying a Support PPC are checked for validity and movement.

#### Buildings
- **Burning buildings tell you what's going on.** Each turn the report shows how much Construction Factor the fire ate and what's left. When it hits 0, the hex comes down right then.
- **Hidden turrets get their point-blank shot.** A revealed hidden unit can turn its turret before firing, and the shot actually goes off.
- **Semi-Guided missiles** fired at a building or hex no longer freeze the game.
- **Bridge heights make sense.** Standing on a bridge or a fuel tank, the Choose Target dialog shows the real height, not -2,147,483,648.

#### VTOLs, WiGEs and Hovercraft
WiGEs got a top-to-bottom pass against Total Warfare and TO:AUE. [What's Coming](https://megamek.org/2026/10/16/0.51.01-what's-coming.html) gave it one line, so here's the whole list.
- **Airborne WiGEs.**
  - No more free cliff climbing (TW p.55).
  - No extra MP going downhill. Keep Elevation is still there if you want it.
  - They can cross low bridges from any direction.
  - Flying over a weak building can bring down the whole hex, not just the top floor.
- **Sideslips, jumps, landings and crashes follow the book.** VTOL and WiGE sideslips (TW pp.67–68), WiGE jumps (TO:AUE p.162), and WiGE landings and crashes all play by their rules now.
- **Grounded WiGEs** follow the hover terrain rules, and support WiGEs play by the same rules as combat WiGEs. A bot with a grounded WiGE takes off again, instead of crawling along 1 hex a turn.
- **Hovercraft and submerged units.** A hovercraft on water can't see or shoot units on the bottom, and they can't see it either.
- **Everything that flies.**
  - Nothing flies in a vacuum. Hovercraft, WiGEs and VTOLs can't operate on a vacuum map, even with Environmental Sealing.
  - Flak keeps its bonus against a VTOL, WiGE or AirMek that flew this turn and then landed.
  - A VTOL or WiGE that deploys airborne can't deploy hidden.
  - Blowing sand no longer damages VTOLs still waiting to enter the map.

About 30 fixes, and almost none of them made it into another post.
- **LAMs.**
  - Artillery flak damages a LAM in AirMek mode.
  - A fallen AirMek gets its Get Up button back.
  - LAMs in AirMek mode can't jump (IO:AE p.102). In Mek mode, they still can.
  - Converting a LAM before it's on the board no longer crashes the game.
- **Fighters.**
  - Cluster weapons fired at ground units work the way the rules say, and missile and rocket hits show their attack value in the report.
  - A fighter that lost control from heat and flew off comes back under control.
  - A fighter pilot hurt while ejecting rolls for consciousness right away.
  - Space battles no longer freeze after an ejected pilot gets picked up.
- **Bombs.**
  - Bomb missiles have the right ranges, and you can actually load LAA and ASEW now.
  - In a bomb run, every bomb rolls its own to-hit, even after one scatters off the board.
  - A Large FAB is one bomb, not two.
- **Large craft.**
  - Weapon bays no longer do negative damage. Yes, that healed the target. Bays and fighter weapons use their attack value again.
  - Firing everything in a big space battle no longer crashes the firing phase.
  - Ammo bins round up to the right tonnage.

  - Units can board a grounded DropShip through a friendly Mek's hex (TW pp.86–91), and cranes can load them.

### New Features
A few more new things:
- **More to build with.**
  - Combat vehicles and conventional fighters get their own Chassis Modifications panels.
  - Large craft fill in the officers they need from their crew size, and new **Auto-Assign Lifeboats** and **Auto-Assign Escape Pods** buttons count everyone aboard, bay crews, passengers and marines included.
  - A weapon can carry more than one enhancement, so a laser can have an insulator and a pulse module together. They stay with their weapon when you sort, move or copy it.
- **Check a unit's tech level.** **Reports > Composite Tech Level** shows the tech level of the unit you're editing, one from the cache, or one from a file, and what it would be under the other tech rule.

- **Around the program.**

- **Omni units keep their fixed equipment fixed.** We said we'd made some improvements to Omnis. If you build them, this one's for you.

  - **Remove All Pods** and **Reset** leave the base chassis alone and only clear the pods.
  - In MekHQ, that means a pod swap stays an OmniPod Reconfiguration instead of turning into a Class F refit.
- **Record sheets that know which rules you play.**

## Data, Licensing & Canonicity

MegaMek, MegaMekLab, MekHQ and MekBay are an unofficial, fan-created implementation of BattleTech. They are not a canon source of BattleTech material.

That's why the programs show a licensing window the first time you start a new release, and why the unit selector lets you filter for canon units and for units with a published record sheet. A unit's canon status comes from the sourcebooks it lists, not from a setting someone flipped by hand.

For the full story, including canon versus official, our data moratorium and what it means for MekBay, and how our Alpha Strike values relate to the Master Unit List, see [Java 21, Version 0.51.0, and a Few Words on Our Data](https://megamek.org/2026/06/05/Java-21-Version-0.51.0-and-Our-Data.html).

### The Launcher Handles Java For You

The easiest way to get 0.51.01 is the [MegaMek Launcher](https://megamek.org/2026/11/02/Feature-Highlight-The-MegaMek-Launcher.html). It installs and manages Java for you, so if you use the Launcher, you can skip the rest of this part. Just remember to update the Launcher whenever it asks.

### Installing by Hand: Java 21 Is Still Required

We strongly recommend you avoid installing by hand and use the new Launcher instead. But if you have to install from the archives (see [Manual Install]({{ '/installing_and_updating.html#manual-install' | relative_url }}) on the Installing and Updating page), for a server, say, or for your own reasons, **Java 21 is still required**. Our guide to [Updating to Adoptium (Eclipse Temurin Open Source Java)](https://github.com/MegaMek/megamek/wiki/Updating-to-Adoptium-(Eclipse-Temurin-Open-Source-Java)) uses Java 17 as the example; simply select Java 21 instead during installation. Everything else in the directions remains the same.

It's crucial to read the directions carefully, especially Step 6, which covers a recent change to the Adoptium installer. Make sure to select "Install for all users of this machine" in the Installation Scope.

If you choose to use a Java version beyond 21 that isn't officially supported, our standard response for issues will be to revert to Java 21.

**WARNING**: If you are running on an older 32-bit OS, **DO NOT INSTALL JAVA 24 or later**, as they have officially dropped support for 32-bit Windows.
